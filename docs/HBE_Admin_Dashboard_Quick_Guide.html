The admin operating model

The Dashboard is a summary and decision screen. The other pages are source screens where records are created, corrected, approved, and completed.

Dashboard shows a signal→Open the source page→Review evidence→Make the change→Return and verify

What the administrator owns

  • Full platform access and team permissions.
  • Final review of artist, rights, financial, and operational records.
  • Approvals, exceptions, security, and data quality.
  • Ensuring work has an owner, deadline, and evidence.

What the dashboard does not do

  • It does not replace the source record.
  • A healthy chart does not prove every file is correct.
  • An alert disappears only when its underlying record changes.
  • Approval should follow review, not simply clear a queue.

Start every session in this order

  1. Read critical and high-priority notifications.
  2. Check pending approvals and items marked Needs Attention.
  3. Review overdue tasks, release dates, contract alerts, and campaign pacing.
  4. Open the matching source page and resolve or assign the issue.
  5. Refresh the Dashboard and confirm the summary changed.
Administrator principleDo not approve from a summary alone. Open the record, check the supporting data or file, then approve and leave notes when an exception is made.

Global controls

Sidebar opens each module. Workspace search finds accessible records. Notification bell opens alerts. Theme changes appearance. User menu opens Profile, Settings, and Sign out.

Dashboard — how to read it

Read from risk to detail. Use each panel as a link in a decision, then work in the relevant module.

Critical / approvals badgesImmediate workload. Open approval and attention records first.
Revenue, profit, artists, releasesExecutive KPIs. Investigate unusual values in Finance, Artists, or Releases.
Performance ringsTask, approval, roster, and contract health. Low percentages identify the operating area to inspect.
Financial breakdownRevenue versus expenses. Reconcile source transactions before interpreting profit.
Task distributionOverdue, due this week, and on-track work. Reassign or update in Tasks.
Artist rosterActive versus inactive artists. Correct lifecycle status in Artists.
Approval queueTasks, songs, and other records waiting for review. Open the original record before approving.
Project momentumProgress, owner, and next deadline. Update Projects and its linked Tasks.
Needs attentionConcentrated operational risk. Resolve the source issue or assign a responsible owner.
Release scheduleUpcoming dates and runway. Check readiness gates in Releases, Metadata, and Ownership.
Campaign statusBudget and execution pacing. Update activity and results in Campaigns.
Contracts / activity / top artistsRenewal risk, recent system changes, and portfolio performance context.

Dashboard response loop

  1. Name the problem: overdue, missing approval, financial variance, readiness gap, or access issue.
  2. Identify the source page using the mappings above.
  3. Open the record and confirm the data is current.
  4. Correct, approve, assign, or document the next action.
  5. Refresh and verify; if unresolved, create a Task with owner and due date.
ExampleUpcoming release + missing readiness → open Releases → identify failed flag → correct Metadata or Ownership → return to Releases → complete the phase checklist → verify the Dashboard schedule.

Core workflows

Artist onboarding

Artists→Add Artist→Identity + business→Documents→Submit→Approve / reject
  1. Create the artist and complete required identity/contact fields.
  2. Add profile, music, business, tax, payment, contract, and social details.
  3. Upload required documents and confirm delivery of the onboarding package.
  4. Submit for approval. Review every section and document from the artist profile.
  5. Approve to generate the artist login, or reject with a clear correction reason.

Song to release

Music Catalog→Production→Metadata→Ownership→Releases→Campaign
  1. Create the song, credits, beat/license details, priority, and owner.
  2. Complete the production steps and upload the required versions.
  3. Create and validate Metadata; fix every validation error.
  4. Enter ownership splits, licenses, samples, and signatures; validate and approve.
  5. Create the Release, verify readiness flags, and progress each checklist phase.
  6. Coordinate promotion in Campaigns and review results in Analytics.

Revenue to royalty

Finance→Royalty period→Calculate→Approve→Pay→Artist Balance
  1. Record and classify income/expense with evidence and links.
  2. Create the artist royalty period and enter source income, fees, deductions, and splits.
  3. Calculate; check contracts, ownership, source totals, and recoupment.
  4. Approve, generate the statement, issue payment, and record its reference.
  5. Update, reconcile, and approve the corresponding Artist Balance.
Never bypass a gate without a recordForced release advances, financial adjustments, ownership approval, and deletion require a documented reason and supporting evidence.

Catalog pages

01

Artists

Purpose: Roster, profiles, onboarding, documents, business information, approval, and artist lifecycle.

  1. Search/filter → open profile or Add Artist.
  2. Complete or review onboarding and attachments.
  3. Approve/reject; keep status and assigned manager current.

Next: Music Catalog, Development, Projects, Contracts, Files.

02

Music Catalog

Purpose: Song master record, production workflow, credits, beat information, and audio versions.

  1. Create song → add artist, credits, status, priority, and ownership details.
  2. Update the 12 production steps and notes.
  3. Upload masters/alternate versions; confirm credits and backups.

Next: Metadata and Ownership, then Releases.

03

Metadata

Purpose: Delivery-ready descriptive, identifier, rights, credit, platform, and technical data for each song.

  1. Create/open the song metadata record.
  2. Complete required fields, writers, publishers, IDs, dates, and technical details.
  3. Validate or bulk validate → correct every error → export if needed.

Next: Ownership validation and Release readiness.

04

Ownership

Purpose: Master/composition splits, publishers, producer, featured artists, beat license, samples, signatures, and registration.

  1. Add every rights participant and document link.
  2. Validate 100% totals, signatures, samples, license, and registration.
  3. Approve only when release-ready.

Next: Releases; evidence belongs in Files.

Catalog ruleA green Release flag must be supported by the underlying Music Catalog, Metadata, Ownership, and Files records.
5

Release and file pages

05

Releases

Purpose: Package songs into a single/EP/album/mixtape/compilation and operate its delivery lifecycle.

  1. Create release → select artist, songs, date, type, owner, and priority.
  2. Verify ownership, master, artwork, and metadata readiness.
  3. Complete current-phase checklist: Preparation → Distribution → Marketing → Post-Release → Completed.
  4. Track each platform as pending, submitted, live, or rejected.

Next: Campaigns, Analytics, Finance, and Royalties.

06

Files

Purpose: Protected working library for artist, song, legal, publishing, accounting, release, and campaign assets.

  1. Initialize storage if required; create artist/song folder structures.
  2. Open the exact destination → upload supported files → add category, tags, and record links.
  3. Preview/download to verify; star, move, or rename when needed.
  4. Confirm primary/cloud/external backup indicators after changes.

Supports every page; link evidence from the source record.

Release readiness check

QuestionWhere to verifyReady when
Is the audio final?Music Catalog + FilesMasters/versions complete and backed up.
Is metadata valid?MetadataValidation returns no blocking errors.
Are rights cleared?Ownership + Contracts + Files100%, signatures, licenses, and samples confirmed.
Is delivery planned?ReleasesDate, platforms, owner, flags, and phase checklist are current.

Delete carefullyCheck linked records before deleting an artist, song, release, folder, or file. Prefer correcting status or archiving where the business must retain history.

Planning and execution pages

07

Projects

Purpose: Group songs and work around a release or business initiative.

  1. Create project → artist, type, dates, priority, budget, manager, and team.
  2. Add songs and milestones; update progress and next action.
  3. Use linked Tasks for accountable work; close only when deliverables are complete.

Feeds Dashboard momentum and connects Songs, Tasks, Releases, and Finance.

08

Tasks

Purpose: Assign and track individual responsibilities on a Kanban board.

  1. Create task → title, status, priority, assignee, dates, and linked records.
  2. Move status as work changes; record blockers and comments.
  3. Confirm completion evidence before marking completed.

Feeds Dashboard task health and Weekly Report follow-through.

09

Weekly Report

Purpose: Capture structured weekly progress, blockers, priorities, decisions, and next actions.

  1. Open Current Week → answer all reporting prompts.
  2. Use source records and task status, not memory alone.
  3. Save/submit → review History for unresolved commitments.

Turn every unresolved item into a Task, Project update, or owner decision.

10

Development

Purpose: Artist development plans, goals, milestones, progress, and scorecards.

  1. Create an artist plan with focus areas and measurable goals.
  2. Add target dates/milestones and update progress regularly.
  3. Open the artist scorecard, record metrics, and adjust priorities.

Connects artist strategy to Projects, Tasks, Campaigns, and Analytics.

One owner, one next actionProjects describe the larger outcome. Tasks describe who does the next piece of work and by when. Weekly Report confirms whether it moved.

Content and relationship pages

11

The Lnk Up

Purpose: Plan and track live-series episodes from concept through air date.

  1. Create episode → title, guest/artist, format, owner, dates, and production state.
  2. Progress planned → casting → recorded → editing → scheduled → aired.
  3. Keep assets, notes, links, and results attached to the episode.

Coordinate Tasks, Contacts, Files, and Campaigns.

12

Campaigns

Purpose: Plan audience, channels, budget, content, advertising tests, dates, and results.

  1. Create campaign → artist/release, goal, audience, budget, owner, and schedule.
  2. Add content calendar items and ad tests; update spend and execution status.
  3. Record reach, clicks, conversions, engagement, and attributed revenue.
  4. Compare outcome to goal/budget; document lessons at completion.

Feeds Dashboard campaign status, Analytics, and Finance.

13

Contacts

Purpose: Maintain press, playlist, venue, distributor, partner, vendor, and other professional relationships.

  1. Search before creating to prevent duplicates.
  2. Add identity, organization, category, channels, tags, and owner.
  3. Record interactions, follow-up date, notes, and linked artist/campaign.

Use Tasks for promised follow-ups and Campaigns for outreach results.

Campaign operating loop

Release goal→Campaign plan→Contacts + content→Spend→Results→Analytics review
Do not confuse activity with outcomePublishing content is an action. Reach, engagement, conversions, revenue, and learning determine whether the campaign worked.
8

Legal pages

14

Contracts

Purpose: Store parties, terms, files, value, dates, renewal/option details, and contract lifecycle.

  1. Create contract → type, title, parties, artist/project, value, dates, owner, and terms.
  2. Attach or link the correct document and version.
  3. Progress draft → pending signature → active; record signed date and renewal/option details.
  4. Review expiring, expired, and renewal-due alerts; assign next action.

Supports Ownership, Releases, Royalties, Artist records, and Finance.

15

Templates

Purpose: Maintain reusable contract starting points and required-field definitions.

  1. Create/edit template → name, category, content, placeholders, active status, and notes.
  2. Review current legal language and variable requirements.
  3. Use as a starting point, then create/review the actual contract.

Produces draft material for Contracts; it is not an executed agreement.

Before changing a contract to Active

  • Correct parties and legal names.
  • Correct contract version and complete signatures.
  • Effective, end, renewal, notice, and option dates verified.
  • Rates, ownership, recoupment, territory, and term match the deal.
  • Executed file stored and linked.
  • Responsible owner and next renewal action assigned.
Legal review requiredThe platform stores operational contract information. Templates and data-entry screens do not replace qualified legal review or authorized signatures.
9

Finance pages

16

Finance

Purpose: Record income/expense, payment state, evidence, allocation, account/tax details, and budget position.

  1. Create transaction → date, type, amount, category, counterparty, and payment status.
  2. Link artist/project/release and attach invoice/receipt evidence.
  3. Reconcile totals, overdue items, and budget variances.

Source data for Dashboard financials, Royalties, Artist Balances, and Analytics.

17

Royalties

Purpose: Calculate artist/label/producer/featured shares, deductions, recoupment, statements, and payments.

  1. Create period → artist, dates, source income, fees, deductions, and splits.
  2. Verify sources equal gross and artist + label equals 100%.
  3. Calculate → review contract/ownership/evidence → approve.
  4. Generate statement → pay → record method, date, and reference.

Updates Artist Balances and artist-facing royalty history.

18

Artist Balances

Purpose: Track period opening balance, income, expenses, advances, royalties, payments, adjustments, and closing balance.

  1. Open/create artist period and add supported transactions.
  2. Explain every adjustment with amount, date, reference, and notes.
  3. Reconcile to source records → approve only when the closing balance agrees.

Supports statements, payment decisions, and finance reporting.

19

Tax Calendar

Purpose: Track filing/payment/estimate/extension obligations by due date and owner.

  1. Create event → type, due date, year/quarter, amount, owner, and recurrence.
  2. Monitor upcoming/overdue items and supporting evidence.
  3. Mark complete only after filing/payment is confirmed.

Create Tasks for preparation and keep confirmation files in Files.

Financial controlWhere staffing permits, separate entry, approval, and payment. Never use an adjustment to conceal an unexplained difference.

Insight pages

20

Analytics

Purpose: Executive, artist, release, marketing, and financial views with filters and export.

  1. Select the correct dashboard/tab and reporting filters.
  2. Read KPI, trend, and comparison values together.
  3. Investigate surprising values in the source module.
  4. Correct source data, refresh, then export the agreed reporting period.

Turns operational records into review and planning decisions.

21

Song Analytics

Purpose: Capture platform performance, audience, commercial results, spend, growth, and notable events for a song/reporting period.

  1. Select song and consistent reporting period.
  2. Enter streams/listeners/saves, audience, revenue, sales, spend, and context.
  3. Save → compare periods → use growth and efficiency measures to decide next action.

Informs Campaigns, Development, Releases, and executive reporting.

How to interpret analytics

SignalQuestionLikely source page
Revenue changedIs it performance, timing, missing data, or classification?Finance / Royalties
Release underperformedWas readiness, audience, content, spend, or timing weak?Releases / Campaigns / Song Analytics
Artist growth slowedWhich platform, audience, content, or development goal changed?Song Analytics / Development
Campaign ROI fellDid cost, conversion rate, attribution, or revenue move?Campaigns / Finance
Use one reporting conventionDo not mix lifetime totals with monthly or campaign-period values. Confirm date range, platform definitions, and currency before comparing.

Account and control pages

22

Team

Purpose: Create accounts, assign roles, update staff details, reset passwords, activate/deactivate, and remove access.

  1. Search before creating → add name, unique email, role, password, and department.
  2. Apply least privilege; change role only for an approved business need.
  3. Deactivate access promptly when no longer required.
  4. Reassign work and records before permanent deletion.

Controls the navigation and actions each person receives at next sign-in.

23

Settings

Purpose: Personal profile, password, two-factor authentication, notifications, appearance, integration links, and permission overview.

  1. Keep profile and notification preferences current.
  2. Use a strong password and enable authenticator-based 2FA.
  3. Save appearance and validated platform links.
  4. Review permissions and open Team when access changes are required.

Supports account security, alerts, and safe platform access.

24

Dashboard

Purpose: Return point for executive triage and verification after source records change.

  1. Refresh after important edits.
  2. Confirm the expected KPI, queue, warning, or schedule changed.
  3. If not, reopen the source record and verify its status/date/link.

The loop closes here, then starts again with the next priority.

Access-change checklist

  • Request and business reason verified.
  • Correct role selected; no unnecessary access granted.
  • Existing tasks/projects/contracts reassigned if responsibility changed.
  • User instructed to sign out and back in after a role change.
  • Departing user deactivated promptly; deletion only after retention review.
Security ruleNever ask users to send passwords or authenticator codes. Administrators can assign/reset access, but credentials must be delivered through an approved secure channel.

Administrator routines

Daily
Notifications → critical issues → approval queue → overdue tasks → upcoming releases → contract/tax warnings → assign owners and deadlines.
Weekly
Weekly Report → project momentum → task ownership → release readiness → campaign pacing → artist development progress → unresolved decisions.
Monthly
Finance reconciliation → royalty inputs → artist balances → analytics period → contract horizon → backup health → access review.
Quarterly
Royalty approval/payment → development scorecards → contract options/renewals → tax plan → least-privilege audit → restore test.

Before approving anything

  • The record is complete and the status reflects reality.
  • Required totals, dates, IDs, and percentages validate.
  • Supporting files are the correct final versions.
  • Linked records agree with one another.
  • Exceptions and overrides include a reason and authorized owner.
  • The next person/action is clear.

When something looks wrong

Do not edit the chart→Find the source→Check date/status/link→Correct once→Refresh and verify
SymptomFirst check
Dashboard number looks wrongSource record date, status, amount, role scope, and links.
Page/action is missingSigned-in role, Team assignment, and sign-out/sign-in after changes.
Release cannot advanceCurrent checklist plus Metadata, Ownership, master, and artwork readiness.
Royalty will not calculateSource total = gross; artist + label = 100%; valid deductions/splits.
Upload rejectedExtension, true file type, size, destination, and connection.
The simplest admin ruleEvery important record should answer: What is it? Who owns it? What state is it in? What evidence supports it? What happens next, and by when?

Platform overview

The platform centralizes the label's artist roster, catalog creation, releases, rights, legal documents, projects, tasks, campaigns, contacts, finance, royalties, tax dates, analytics, files, and team access.

Catalog & rights

Artists, songs, versions, metadata, ownership splits, clearances, signatures, and release readiness.

Operations

Projects, task Kanban, weekly reporting, development plans, scorecards, and show episodes.

Finance & legal

Transactions, budgets, contracts, templates, royalty calculations, balances, payments, and tax deadlines.

Marketing & insights

Campaign plans, content calendars, contacts, performance metrics, dashboards, and CSV reports.

Typical information flow

Artist→Song→Metadata + Ownership→Release→Campaign→Revenue→Royalty + Artist Balance

Projects and tasks can coordinate the work across this lifecycle. The File Manager stores related business assets, while dashboards and analytics summarize the resulting records.

Record-management pattern

  1. Open a module from the left navigation.
  2. Use search, filters, tabs, or cards to locate a record.
  3. Select a record to view details; use the pencil/edit action to change it.
  4. Complete required fields, save, and confirm the success notification.
  5. Use delete only after confirming dependencies and retention requirements.

Sign in and sign out

Sign in

  1. Open the platform login page.
  2. Enter the email address assigned by the administrator.
  3. Enter the password. Use the eye icon to show or hide it.
  4. Select Sign In. A confirmation screen appears while the correct role dashboard loads.
First-time accessAn artist can select Create an account; the system creates both the artist login and linked starter profile. Administrators create staff accounts and assign roles in Team Management.

Password recovery and two-factor sign-in

  1. Select Forgot password?, enter the account email, and submit.
  2. Open the time-limited link delivered by the configured recovery service. Development/demo deployments can load the one-time code directly.
  3. Enter and confirm a new password of at least eight characters.
  4. If two-factor authentication is enabled, complete password sign-in with the current six-digit authenticator code.

Keep me signed in stores the session persistently in that browser. Leave it clear to use session storage, which ends when the browser session closes.

Login errors

Message or symptomMeaning / action
Invalid credentialsRe-enter the email and password exactly. Confirm Caps Lock and keyboard language.
Account is deactivatedAsk an administrator to reactivate the member in Team Management.
Returned to login during workThe stored session may be expired or stale. Sign in again. Unsaved form content may need to be re-entered.

Sign out

Select the user avatar at the top right and choose Sign out, or select Sign Out at the bottom of the sidebar. Signing out clears locally stored account, navigation, access, and session details.

Shared devicesLeave Keep me signed in clear and always sign out after use. Signing out clears both persistent and session-scoped application credentials.

Artist onboarding workflow

Create artist→Personal details→Music/business data→Documents→Package acknowledgment→Submit→Approve / Reject
  1. Administrator or Manager opens Artists > Add Artist.
  2. Complete required legal name, stage name, email, phone, and primary genre. Add contact, biography, social and image information.
  3. Save the first step. The artist record must exist before profile/cover images and documents can be attached.
  4. Add music links, previous releases, existing catalog ownership, PRO/publisher, payment, tax, contract dates, manager, royalty rate, and notes as applicable.
  5. Upload every required onboarding document and download/deliver the onboarding package.
  6. Confirm that the artist received and reviewed the package. Add onboarding notes and select Submit for Approval.
  7. An Administrator or Manager opens the profile, reviews all data/documents, and selects Approve or Reject. Rejection should include a clear reason.
  8. If rejected, reopen onboarding, correct the record, replace documents if needed, and resubmit.

Required document set

Artist agreement, tax form, NDA, image release, payment instructions, code of conduct, social media expectations, recording delivery requirements, and existing contract where applicable. Document status can be pending, approved, or rejected.

Approval gateSubmission is blocked until required onboarding documents are present and the package acknowledgment is confirmed.
7

Music-to-release workflow

Create song→12 production steps→Versions + credits→Metadata validation→Ownership validation→Create release→4 release phases
  1. Create the song with artist, status, priority, production information, credits, and beat information.
  2. Move each production step through pending, in progress, completed, or blocked; document blockers in notes.
  3. Upload alternate deliverables such as explicit/clean masters, instrumental, performance, a cappella, radio edit, stems, high-quality WAV, and reference MP3.
  4. Create metadata, complete identifiers/rights/technical/platform fields, and run validation. Resolve every listed error.
  5. Create the ownership record. Enter all writers, publishers, producer, featured artists, beat license, samples, and required signatures. Ensure the combined percentage equals 100%.
  6. Validate ownership; obtain signatures and clear samples. Approve ownership only when release-ready.
  7. Create the release with at least one song, date, type, status, platform delivery information, and readiness flags.
  8. Complete the current phase checklist, then advance: Preparation → Distribution → Marketing → Post-Release → Completed.
Do not force a phase casuallyThe phase-advance control may offer a forced advance when checklist requirements are incomplete. Use it only with documented approval because it bypasses the intended operational gate.
8

Finance-to-royalty workflow

Record income/expense→Attach evidence→Monitor budget→Create royalty period→Calculate→Approve→Pay→Reconcile balance
  1. Finance user records income and expenses with dates, category, counterparty, links to artist/project/release, payment status, method, invoice/receipt, account reference, and tax classification.
  2. Maintain budgets and line items. Compare budgeted against spent; investigate overruns.
  3. Create the royalty period for an artist and optionally link the release, song, contract, ownership, finance transactions, and supporting files.
  4. Enter gross income by source, fees, approved deductions, recoupable expense position, and split percentages. Source income must equal gross income; artist plus label must equal 100%.
  5. Select Calculate. Review net income, shares, recoupment, producer/featured allocations, and remaining balance.
  6. Approve only after the underlying contract, ownership, source reports, deductions, and bank/payment information have been checked.
  7. Generate the statement record, issue payment, and record amount, date, method, reference, and notes. The platform updates paid and remaining amounts.
  8. Update the artist balance period and add supporting income, expense, advance, payment, or adjustment transactions; reconcile and approve under the label's financial controls.
Separation of dutiesWhere staffing permits, the person entering a calculation should not be the only person approving and paying it. Keep source evidence in the File Manager.

The Metadata Manager creates one metadata record per song, displays validity statistics, supports individual/bulk validation, editing, deletion, and export.

GroupFields

Validation rules

  • Required: title, version, artist, genre, language, label, ISRC, UPC, copyright owner, release date, lyrics, BPM, key, and contact email.
  • ISRC must normalize to 12 valid characters; UPC must contain 12 or 13 digits.
  • At least one writer/composer and at least one producer are required.
  • Writer percentages must total 100%; at least one publisher (including self-published) and publisher percentages totaling 100% are required.

Validation states: valid, incomplete, needs review, unvalidated. Export records the format and time when supported.

15. Tasks & Responsibilities

Access: Administrator RW; Manager RW; Artist/Finance/Marketing assigned tasks R + comments

The task board is a Kanban workflow with summary statistics and team-performance information. Columns are Not Started, In Progress, Waiting Approval, Blocked, Delayed, and Completed.

Create a task

Complete title*, description, assignee, related project, related artist, deadline*, status, priority, category, deliverable, tags, and notes. Categories: production, marketing, finance, legal, distribution, and general.

Operate the board

  1. Create the task with a specific deliverable and accountable assignee.
  2. Open a card for full details or change its status from the detail view.
  3. Move it to In Progress only when work has begun.
  4. Use Blocked with a note describing the blocker and needed owner; use Delayed when the committed date is missed or formally moved.
  5. Use Waiting Approval for submitted work and Completed only after acceptance. Completion time is recorded automatically.

Statistics include total, by status, by priority, overdue, and due this week. Team performance includes completed, delayed, in-progress, critical, on-time, completion rate, and on-time rate.

Task hygieneUse one clear outcome per task. A task title should be understandable without opening it; the deliverable field should define what “done” means.

16. Weekly Report

Access: Administrator RW; Manager RW (route available; see deployment notes)

The platform creates/returns the current reporting week and provides a structured check-in with a completion meter. The History tab lists prior reports, author, date range, completeness, and delete action.

Seven reporting prompts

  1. What was completed?
  2. What is still open?
  3. What is blocked?
  4. What needs approval?
  5. What is due this week?
  6. What is the biggest risk?
  7. Who owns next action?

An Additional Notes area captures context that does not fit the seven prompts. All fields are recommended; the completion meter is the percentage of the seven prompts containing text.

  1. Open the current week.
  2. Write concise bullets or short paragraphs under each prompt.
  3. Name the owner and the exact next action.
  4. Select Save Report and confirm the success message.
  5. Use History for review; delete only in the case of a duplicate or approved retention action.

24. Royalties

Access: Administrator RW; Finance RW; Artist own statements R

The royalty ledger manages an artist/period from draft through calculation, approval, and payment. Search/filter entries, open detail, calculate, generate a statement record, approve, record payments, edit, or delete according to role.

GroupFields and rules
ScopeArtist*, period*, start/end*, optional release, song, contract, ownership, finance transactions, supporting files.
IncomeGross income and streaming, publishing, mechanical, performance, sync, merchandise, other. Non-zero source total must equal gross.
DeductionsDistributor fees; itemized approved deductions with description, amount, and recoupable/non-recoupable/tax/other category.
RecoupmentRecoupable expenses, previously recouped, recouped this period, remaining recoupable.
SplitsArtist + label must equal 100%; producer + featured artist cannot exceed artist percentage.
CalculatedNet income, artist gross/net share, label share, producer/featured royalty, remaining balance.
PaymentsAmount*, date*, method, reference, notes; total paid and remaining balance are tracked.

Status: draft, calculated, approved, paid, disputed. Period end must be on/after period start.

Safe processing sequence

  1. Create and link source records.
  2. Enter income, deductions, recoupment, and splits.
  3. Calculate and independently review.
  4. Resolve disputes before approval.
  5. Approve and generate the statement.
  6. Open the statement and select Print / PDF; use the browser print dialog to print or save a PDF.
  7. Pay and immediately record payment details.

25. Artist Balances

Access: Administrator RW; Finance RW

Artist Balances gives a period-based balance view and transaction history. Search artists, create a balance record, open details, add a transaction, and delete after confirmation.

Balance data includes artist*, period*, period start/end*, opening balance, income, expenses, advances, royalty payments, closing balance, notes, and draft/reconciled/approved status. The current interface may present summary names such as current balance, total earned, total paid, total advances, and advance remaining depending on loaded data.

Add transaction

Select income, expense, advance, payment, or adjustment; enter a non-zero amount, required description, reference, date, and notes. The interface indicates that negative amounts may be used for debit-style adjustments. Check the updated closing balance and history after saving.

ReconciliationDo not use an adjustment to hide an unexplained difference. Link it to a reference and explain the business reason in notes.

29. File Manager

Access: Administrator RW; Manager RW

The protected file library supports initialization, folders, structured artist/song trees, upload, preview, download, search, star, move, rename, delete, and verified backup to configured cloud/external destinations.

Initialize and structure

Initialize Storage creates missing root folders: Artists, Releases, Publishing, Accounting, Legal, Merchandise, and Templates.

Artist structure creates the named artist under Artists with Music, Contracts, Photos, Videos, Marketing, and Royalties. Inside an artist's Music folder, Song structure creates Recording Session, Beat, Stems, Rough Mixes, Final Masters, Artwork, Lyrics, Split Sheet, Producer Agreement, Metadata Sheet, and Content Assets.

Upload and manage

  1. Open the destination folder.
  2. Select/upload up to 20 supported files in a request and add category/tags/record links where offered.
  3. Confirm each file appears and preview protected image/audio/video/PDF content where the browser supports it.
  4. Star important files, move or rename when needed, and refresh backups after a move/rename.
  5. Use Download for an authorized copy. Downloads are counted.

Supported extensions: PDF, DOC/DOCX, TXT, CSV, XLS/XLSX, JPG/JPEG/PNG/WEBP/GIF, MP3/WAV/FLAC/AAC/M4A/AIFF, MP4/MOV/AVI/WEBM, ZIP/RAR/7Z. Executables, HTML, scripts, and SVG are intentionally excluded. Default maximum is 500 MB per file (deployment-configurable).

Backup indicators

Primary, cloud, and external flags are checksum-verified; a file is “healthy” when all three are verified. Cloud/external actions require configured mounted destinations. Moving/renaming primary content invalidates old backup flags until re-backed up.

Deletion scopeDeleting a folder can affect nested folders/files. Confirm the exact breadcrumb and business retention requirement before accepting deletion.

31. Settings and notifications

Personal settings and notification bell: all roles. Permissions and Team Management: Administrator only.

Profile

Change name, phone, department, and avatar; email and role are displayed but disabled. Images must be under 3 MB in the client and are stored as an image data URI within the server limit. Remove the photo with X and select Save Changes.

Security

Change password with current password, new password, and confirmation. To enable two-factor authentication, select the toggle, add the displayed setup key to any standards-based authenticator app, enter the current six-digit code, and verify. Disabling 2FA requires the current password.

Notification preferences

Toggle and save task deadline alerts, release reminders, contract expiry warnings, approval requests, finance reports, and campaign updates. The bell polls unread count every minute and loads the latest 20 items when opened.

Appearance, integrations, permissions

Choose Light, Light Indigo, Light Warm, or Dark plus small/default/large font sizing, then select Save Changes; the choice is applied and retained. Platform Integrations stores validated Spotify, Apple Music, and distributor web links for one-click access. It does not claim to import private platform data. Administrators also see the permissions overview and Team Management link.

Notification actions

Select an item to follow its link; use the check to mark one read, Mark all read for all, or trash to delete where authorized. High-priority alerts use a red priority dot and are counted in the footer.

Operating standards

Data quality

  • Use consistent artist and project naming; search before creating a duplicate.
  • Enter ISO identifiers exactly and use metadata validation before distribution.
  • Keep split totals at 100% and store executed rights documents.
  • Use reporting period names consistently (for example 2026-Q3 or 2026-09).
  • Record money as positive transaction amounts with type/category defining direction, except explicit adjustment workflows that state otherwise.
  • Use references on payments, adjustments, invoices, and deductions.
  • Update status as soon as the business state changes.

Approval and audit discipline

  • Review source files before marking ownership, contract, release, royalty, or balance approved.
  • Explain forced phase advances, overrides, rejections, and adjustments in notes.
  • Do not share passwords or reuse a departing employee's account.
  • Deactivate access promptly, then reassign tasks, projects, contracts, campaigns, and files before deletion.

File naming recommendation

Artist_Project_DocumentType_YYYY-MM-DD_v01.ext, for example AvaRay_NightDrive_SplitSheet_2026-09-10_v02.pdf. Keep the final executed copy clearly distinguishable from drafts.
